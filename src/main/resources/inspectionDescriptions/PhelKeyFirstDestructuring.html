Reports map destructuring pairs written key-first, {:name n}, which Phel 0.51 deprecated in favour of the Clojure order, {n :name}. The compiler reports the same under --warn-deprecations, and the key-first order is announced for removal in a future release.

Only patterns are inspected: the name half of a let-like binding vector and the entries of a function's parameter vector, nested patterns included. An ordinary map literal is never a pattern, and neither is the :or map of defaults, whose keys name bindings rather than introduce them. The :keys, :strs, :syms and :as directives are unchanged and are not reported.

DeprecatedWrite instead
(let [{:name n :age a} user] ...)(let [{n :name a :age} user] ...)
(defn f [{:id id}] ...)(defn f [{id :id}] ...)
{:address {:keys [city]}}{{:keys [city]} :address}
{0 a 1 b}{a 0 b 1}

The quick fix swaps the two halves of the pair. It is offered only when the pair is unambiguous, which is when the key is something that cannot be bound to: a keyword, a string or a number. A pair whose two sides are both symbols, {k v}, is still read key-first by the compiler, which evaluates k as the lookup key. Swapping it would silently change which side is looked up, so it is reported as a weak warning with no fix, and the advice is to write the key as a keyword or a string.
