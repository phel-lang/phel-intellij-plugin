Reports a bare symbol that names nothing in scope.

Phel's analyzer resolves a symbol against local bindings, then the current namespace's globals, then use aliases, then phel.core. When none of them has the name it raises PHEL001 Cannot resolve symbol and compilation fails, so this reports a build error rather than a style problem. The most common cause is a missing (:require ...).

Example:


(defn my-function [a b]
  (+ a b inexistent-param))  ;; 'inexistent-param' is reported

Qualified symbols such as str/join are reported separately, as an unresolved namespace or an unresolved function within a known namespace.

What is never reported

The inspection is deliberately conservative — it stays quiet wherever it cannot be certain, because a false report on working code is worse than a missed one:

  • Quoted and syntax-quoted forms ('foo, `foo), which are data rather than references.
  • Anything inside a call to a macro defined in the project. A macro's expansion can bind names that appear nowhere in the source, and the plugin does not expand macros.
  • PHP interop: php/..., (.method obj), (Class. ...) and classes brought in through (:use ...).
  • The names a definition or binding introduces, which declare rather than reference.
