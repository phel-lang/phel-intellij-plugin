Reports the source forms Phel 0.52 removed as source, which the compiler rejects with PHEL012. There is no flag to turn it off: a file that writes one of these no longer compiles.

The rule behind the interop entries is that php/ means host access, and is never a second spelling for something Phel already says the Clojure way. These four remain the target the Clojure-style shorthand expands to, so generated PHP is unchanged and a macro that expands to one keeps working. They still appear in completion for that reason. What changed in 0.52 is only that writing one yourself is an error.

Removed as sourceWrite instead
(php/new Foo arg)(Foo. arg) or (new Foo arg)
(php/-> obj (method arg))(.method obj arg) or (.-field obj)
(php/:: Foo (method arg))(Foo/method arg) or Foo/CONST
(set-var v x)(alter-var-root #'v f), or (set! v x) for the current binding frame

The rest of the php/ family is not reported. php/aget, php/aset, php/apush, php/aunset, php/oset, php/ref and php/callable each reach a PHP capability Phel has no other word for, so they are current and stay valid source.

No quick-fix is offered: every replacement here reorders or re-nests the call's arguments, so there is no text substitution that would be correct in general.
