Reports a private top-level definition that nothing in its own file references.

Privacy is what makes this answerable: a public definition can be called from any other namespace, so its own file cannot tell whether it is used. A private one is reachable only from where it is declared, so a file-local scan is conclusive.

Recognises all three ways Phel marks a definition private: the defn- / def- / defmacro- family, a ^:private flag on the name, and a :private entry in the metadata slot.

Example:


(defn- helper [x]   ;; reported: Private definition 'helper' is never used.
  (* x 2))

(defn public-entry [x]
  (* x 3))

Not reported

A definition that refers to itself stays alive: reporting a recursive helper as unused would be wrong far more often than the reverse.

No quick-fix is offered. Deleting a definition is a larger step than deleting a binding, and a name reached only through a macro would be gone before it was missed.
